## 2025-06-11 - Interactive styles applied to non-semantic wrappers
**Learning:** Found a pattern where interactive styles (like `hover:bg-gray-700`, `cursor-pointer`, and `transition`) are applied to a parent `<div>` instead of the semantic `<button>` element itself. This breaks standard keyboard navigation focus rings since the focus goes to the inner `<button>` while hover state visual feedback happens on the parent `<div>`. Additionally, these icon-only buttons lacked `aria-label`s.
**Action:** When fixing icon-only buttons in this codebase, ensure that interactive styles (hover, focus-visible) are moved from the parent `<div>` wrapper directly onto the `<button>` element, add `focus-visible:ring-2` to ensure keyboard focus visibility, and add descriptive `aria-label`s.
