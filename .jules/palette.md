## 2024-07-14 - Semantic Button Accessibility
**Learning:** Interactive styles (hover, focus, transitions, tooltips) on icon-only buttons are incorrectly applied to non-interactive `<div>` wrappers instead of the semantic `<button>` element itself. This pattern prevents keyboard users from seeing focus states and breaks screen reader interaction because the wrapper visually changes, but the semantic button (which receives the focus/events) lacks these visual cues and `aria-label`s.
**Action:** When adding accessibility to interactive components, always move visual interactive styles (like `hover:bg-gray-700`, `transition`) directly to the semantic interactive element (`<button>`, `<a>`). Add `aria-label` for screen readers and explicit `focus-visible:ring-*` styles for keyboard navigation on the same element.
