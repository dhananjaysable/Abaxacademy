## 2024-05-17 - Interactive Elements and Semantic Buttons in Abax Academy
**Learning:** Found a specific pattern in this application's components (`Header.jsx`) where icon-only interactive UI elements were structured as an empty `<button>` nested within a `<div>` that handled all the visual styling, sizing, and interactive states (e.g., hover effects). This creates an accessibility gap because screen readers and keyboard users interact with the `<button>`, which lacks the styling cues, descriptive label (`aria-label`), and clear focus indicators that sighted mouse users experience from the surrounding `<div>`.
**Action:** When working on navigation or header components in this app, always ensure that structural interactive styles (like padding, background hover, border-radius) are applied directly to semantic elements (like `<button>` or `<a>`) instead of generic wrapper `<div>`s, while also including explicit `aria-label`s and visible keyboard focus states (`focus-visible:ring`).
