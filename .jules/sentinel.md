## 2025-04-22 - Disabled ESLint Security Rule and Missing Form Validation
**Vulnerability:** The ESLint security rule `react/jsx-no-target-blank` was explicitly disabled (`'off'`) in `eslint.config.js`. This exposes the application to reverse tabnabbing vulnerabilities when using `<a target="_blank">` without `rel="noopener noreferrer"`. Additionally, form inputs in `DirectionsRegistration.jsx` lacked length limits, type enforcement, and HTML validation.
**Learning:** Security rules are sometimes disabled to bypass warnings during development without fully understanding the security implications (like reverse tabnabbing). Forms often omit basic HTML validation which can lead to bad data or unexpected behavior. Default form submissions in React without an API backend can inadvertently cause a GET request that places submitted PII (like emails and phone numbers) directly into the URL string.
**Prevention:** Always maintain ESLint security rules at `'error'` or `'warn'` level. Never explicitly disable them globally. Ensure all frontend form inputs have reasonable length constraints (`maxLength`), required attributes, and proper semantic input types (`tel`, `email`). Implement `e.preventDefault()` on forms to prevent default GET submissions that might leak data in the URL.
